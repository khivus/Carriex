# Публичные выпуски приложения

Приложение один раз при запуске проверяет
`https://api.github.com/repos/khivus/Carriex/releases/latest` без токена аккаунта.
Закрытый репозиторий или отсутствие выпуска дают 404 и не мешают запуску.
После публикации репозитория и выпуска проверка начнёт работать без встроенных
секретов. Источник меняется параметром сборки
`-PcarriexUpdateRepository=owner/repository`.

Создайте стабильный выпуск GitHub с числовым тегом, например `v1.11`, описанием
изменений и **подписанным универсальным APK**. Имя версии Android должно
совпадать с тегом, а код версии — превышать установленный. Текущая версия
разработки: `1.10`, код `11`. Используйте один ID приложения и один ключ подписи
для всех обновлений. Подписанный APK можно экспортировать в Android Studio;
одна команда `assembleRelease` не настраивает подпись выпуска. Не публикуйте
отладочный APK. Рекомендуется один `Carriex-v1.11-universal.apk`; при отдельных
APK для архитектур укажите в именах стандартные названия Android ABI.

Экран обновления показывает изменения, кнопки загрузки/установки и закрытия,
а также флажок пропуска ровно этого тега. Ручная проверка в настройках позволяет
вернуться к пропущенному выпуску. Черновики, предварительные и старые версии,
а также выпуски без подходящего APK игнорируются. Загрузка ограничена заявленным
размером и 300 МБ. При наличии сверяется SHA-256 из GitHub, затем проверяются ID,
возрастание кода версии, минимальная версия Android и ключ подписи APK. Android
запрашивает разрешение источника установки и показывает свой установщик;
скрытой установки нет. Неудачную или прерванную загрузку можно повторить.

Ответ сервера `/health` отдельно сообщает версию и небольшой манифест
совместимости. Номера выпусков приложения и сервера независимы. Протокол 3
и диапазон кодов приложения определяют полную, частичную или отсутствующую
совместимость. При отсутствии метаданных показывается частичная совместимость.
Несовместимый сервер отклоняется до аутентификации устройства. Подсказка ведёт
к выпускам приложения или предлагает попросить владельца обновить сервер.
Владельцам сервера следует проверять диапазон при изменении протокола или
добавлении поддержки нового выпуска приложения.

Живую загрузку и установку из GitHub можно проверить после публикации более
нового подписанного выпуска. Локальные тесты проверяют выбор выпуска,
сравнение версий, совместимость и интерфейс Android независимо от видимости
репозитория.
